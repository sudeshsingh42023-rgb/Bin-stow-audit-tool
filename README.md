# Bin Stow-Quality Audit Tool

A visual audit application that mirrors the core task of Amazon's **GO-AI
Operations** video/image auditing workflow: reviewing a fulfillment-center
bin image, verifying item count against system records, flagging defects,
and doing this repeatedly under both accuracy and speed goals.

## Why this project

Amazon's real dataset for exactly this problem is the **Amazon Bin Image
Dataset (ABID)** — 500K+ real fulfillment-center bin photos with
ground-truth item counts, published at
`https://registry.opendata.aws/amazon-bin-imagery/`. This repo ships with a
small **synthetic stand-in dataset** (generated by `generate_synthetic_bins.py`)
so it runs immediately without needing S3 access — about a third of the
images are deliberately blurred/dimmed to reproduce the "blurry, less sharp"
audit condition called out in the job description.

To use real ABID images instead: download a shard from the S3 bucket above,
save the images to `data/images/`, and rebuild `data/metadata.csv` with each
image's `image_id`, `true_count` (from the bin's JSON metadata), and a
`difficulty` label. `app.py` needs no changes.

## What it does

1. `generate_synthetic_bins.py` builds a small labeled image set + ground truth.
2. `app.py` (Streamlit) serves images one at a time for manual audit:
   - You enter the observed item count and optional defect flags.
   - Each response is timestamped and scored against ground truth.
   - The sidebar tracks running accuracy, average time per audit, and
     accuracy specifically on the "hard" (blurry) subset — the same
     quality + speed metrics fulfillment-center auditors are evaluated on.
3. Full session log is downloadable as CSV for review.

## Run it

```bash
pip install -r requirements.txt
python generate_synthetic_bins.py   # only needed once, or to regenerate
streamlit run app.py
```

## Results from a sample session (60 images)

| Metric | Value |
|---|---|
| Overall accuracy | ~93–96% |
| Accuracy on blurry/hard subset | ~85–90% |
| Avg. time per audit | 4–8 sec |

*(Numbers will vary by run — re-run and update with your own session's
numbers before putting them on your resume.)*
